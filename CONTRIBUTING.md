# Contributing / Issue Reports

This is an early applied-research preview. Small, reproducible reports are more useful than broad feature requests.

When reporting a behavior, include:

1. exact natural-language task;
2. model ID and reasoning setting;
3. whether the run started from a program restart or `ZERO ALL`;
4. relevant `observe_scene` output;
5. the failed skill's `SKILL CONTRACT` and `PHYSICAL VERIFY` result;
6. planning/safety recovery lines around the failure;
7. whether the object moved unexpectedly.

Do **not** include API keys or other secrets.
